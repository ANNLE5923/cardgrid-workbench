## 2. 页面行为与命令对应

- 定义表单字段：名称、预设时长（5 的倍数或留空）、分类、颜色、父定义、完成标准、启用、最低限度；项目/目标关联在保存时原样保留（不在 2D 管理）。
- 新建定义：SaveDefinition `{id:null, expectedVersion:null, ...}`；编辑：携带原 id 与 expectedVersion；归档：ArchiveDefinition（领域层映射为 enabled=false 并升版本）。
- 配置导入：previewDefinitions 列出 merge/replace 差异、前后计数与停用清单；提交 ImportDefinitions 前必须生成并确认完整备份（沿用备份门禁，未绕过）。
- 抽卡：suggest 只返回建议，不创建实例、不占时、不生事实；空候选 `definition=null` 时给出可理解说明与去向。
- 接受建议：AcceptOffer（领域层映射为 AcceptDefinition，生成 instanceId），经 makeInstance 同时写入 instances 与 handOrder；接受后自动切到手牌视图。
- 手牌排序：上下移动按完整 handOrder 排列提交 ReorderHand（领域层要求包含全部手牌且不重复）。
- 撤出 / 放回：WithdrawInstance 改 state=withdrawn 并移出 handOrder；ReturnWithdrawnToHand（领域层 ReturnToHand）改回 open 并追加 handOrder；有活动计划时撤出被 Host 拒绝，页面显示其错误。

## 3. 边界保证（未越界）

- 页面只消费冻结 Host 的公开方法与生产类型，未复制 docs/prototypes 类型或内存 Host，未在页面补占用 / 冲突算法（含 2C-GAP-01，仍由 Host 负责）。
- 定义表单沿用生产校验，未在页面放宽；错误信息直接展示 Host 返回；事实不可编辑 / 撤回 / 删除的语义未触碰。
- 编辑 / 归档定义不修改任何已生成实例的 creationSnapshot/currentContent。
- 失败保留输入：保存期间表单状态不被清空；revision 冲突 / 工作区替换时自动重新读取 token，表单输入仍在，可重新提交。
- 未改任何受保护核心文件；新增页面为未跟踪文件。
