## 1. 冻结结论与优先级

优先级：用户最新决定 → 本文及 D018—D020 → 1C → 1A。本文批准阶段2按字段合同实现并使用合成数据验证，不授权真实数据迁移。1A/1B/1E保留历史证据，不重写成事后全通过。旧计划里“只能空闲打出、双十二小时同时给候选、底部方框容器、释放即保存”不再是实施要求。

| 原待决项 | 1F 结论 | 依据及边界 |
| --- | --- | --- |
| P01 定义来源 | 新定义统一由行动执行域管理；表单/高级 JSON 共用校验与命令；旧配置包保留显式导入和差异预览 | 用户在本轮已选择；停止 Config 与 Planner 双写，不取消兼容入口 |
| P02 实例范围 | 一个实例最多一个活动计划、一个事实；重复行动新建实例 | 用户在本轮明确选择最小闭环；多会话拆分不进入阶段 2 |
| P03 实际时间 | 分钟精度，允许提前确认未来结束，确认后立即锁定 | D011、D015、D016；不新增未来结束拒绝条件 |
| P04 过去日期 | 普通未确认计划允许调整/撤回并留历史；过去例行的原结果不重写，补做或迟补记另建实例并带来源 | D006、V003；不自动把昨日未完成滚入今日 |
| P05 读取与准备 | 加载/导出/切日期完全只读；明确“准备这一天”才提交 PrepareDay | D012、D013；未准备日期可显示标注为“未保存”的模板投影 |
| P06 占时与日终 | 固定安排、活动计划、事实实际区间取并集；原计划只对照；当地日结束自动填红并重算 | D017；红色不持久化、不阻止编辑、不生成事实 |
| P07 几何与选择 | 双环同时显示、底部固定指针、12 个数字随盘转；00:00–24:00 两圈且不绕回 | 用户修订和 1D/1E；正式几何实现放在阶段 3，不把当前动效参数冻结为最终值 |
| P08 固定日程完成 | 阶段 2 固定日程仅作安排；需要实际记录时另建行动卡 | 用户在本轮明确选择；固定安排没有隐式完成入口 |

模板批量应用也遵守用户“所有类型允许重叠、明确提示后保存”的决定：先保护手动例外/事实/卡牌，再对新增或改变的区间完整预览；有重叠须明确确认后原子应用。1C 的保守候选“任何新增重叠一律拒绝”由此替换。未确认重叠仍整次拒绝，不能静默跳过部分条目。

## 2. 阶段 2 身份与状态合同

- 定义是可复用说明；建议是只读临时对象；接受建议/手选才创建行动实例。Inbox 转行动保留 Capture 原文和一次性转换关系，不自动进入 Top3 或占时。
- 定义有 definitionId/version/title/criteria/presetMinutes/enabled/categoryRef/source；新预设 5—1440 分钟、5 的倍数。实例可无时长并留手牌，安排前必须补齐。抽取仅从已启用且适合当前筛选的定义中等概率选择，不引入权重、积分或 AI 自动安排；重抽不产生实例，候选为空给空态。
- 实例有 instanceId/version、不可变 creationSnapshot、可编辑 currentContent、definitionRef/source、createdAt、targetDate、open/withdrawn。目标日期只是意向标签。已安排/已确认由活动计划与事实关系推导，不再维护第二份 done 状态。
- 手牌只存有序 instanceId 引用；必须恰好覆盖 open 且无活动计划/事实的实例。回收追加到手牌末尾，重新排序由用户明确操作；不能复制一个新实例。
- 计划有 planId/version/instanceId/range/contentSnapshot/status。移动保留 planId；撤回标 retracted，确认标 confirmed，均保留旧计划。再次打出产生新 planId。调整实例内容不改历史快照；有活动计划时改时长必须经完整排期预览原子提交。
- 事实有 factId/instanceId、确认内容快照、actualRange、plannedSnapshot 或 null、confirmedAt、来源。每实例最多一条；普通业务保存要求旧事实集合是新集合的逐字段不变子集。无“解锁事实”“撤销完成”“修改已存在批注”命令。
- 批注有 annotationId/factId/text/createdAt，只能追加。原事实/旧批注内容、排序及标识保持；说明写错仍追加下一条。
- 固定安排有 commitmentId/version/range、所属日与模板来源、是否当天手动覆盖；移动/取消需单对象、单版本、单次显式授权。模板管理权限不能借道修改手动块、行动计划或事实。
- 例行保留 ruleId/date 唯一性和 makeupOf 唯一关联；普通时钟推进只派生“已错过”，不在读取时写 History。历史 missed/skipped/cancelled 保留；新的 PrepareDay 不批量重写历史日。Top3 上限 3、活动项目 WIP=3、手动 Minimum Day 继续保留。

## 3. 写入、预览与手势

正式 UI 只提交命令，不复制 Data 修改后直接 commit。领域执行器在一次 IndexedDB 读写事务中读取当前状态、校验 epoch、检查成功回执、校验 revision、重新校验命令/关联/重叠、写 Data/History/回执/恢复点，事务完成后才发布成功。

| 情况 | 冻结行为 |
| --- | --- |
| 同 commandId、相同内容重试 | 返回原结果引用和当前令牌；先查成功回执再检查旧 revision |
| 同 commandId、不同内容 | COMMAND_ID_REUSED；无写入 |
| 两个请求完成同一实例 | 最多一个事实；过期请求先 REVISION_CONFLICT，刷新后 ALREADY_CONFIRMED |
| 预览后其他窗口写入 | 原凭据/授权失效，重新读取并预览；不自动重放 |
| 完整区间重叠 | 列出全部对象及精确交集；带绑定当前输入、版本、冲突集合的确认凭据后允许保存 |
| 区间比空隙长 | 保留全部预设时长；可选择新落点或明确确认重叠，绝不拼接空隙、截短或覆盖对象 |
| STORAGE_FAILED | 原状态和恢复点保持；草稿/命令 ID 保留，可用同请求重试 |
| WORKSPACE_REPLACED | 清除旧选中、预览、授权和业务草稿，加载新 epoch；不能用旧草稿覆盖新工作区 |

只有成功命令追加有意义的 History；一帧拖动、时钟推进、查询、预览、浏览和动画不写业务历史。失败也不写“成功”回执。

固定授权在取消、一次提交结果、切日期/页面、重新加载、token 改变时失效。失败输入可以保留，但必须重新解锁和预览；没有隐形超时。重叠许可与固定解锁是两份不同依据。

卡牌查看浮窗或独立手牌可向盘上拖动。出现虚拟滑块后松手，仅保留未提交预览；无预览处松手回手牌。预览滑块拉出表盘外缘并松手只取消预览；已保存的卡牌计划外拉松手执行 RetractPlan，成功才回手牌。跨内外圈仍调半日；固定安排/事实不变成手牌。回收失败显示原计划与重试入口，不能先永久移走图形。

“浮窗坐标/抖动/形变/展开角度/选择”仅本次页面会话有效；手牌顺序仅明确 ReorderHand 命令持久化。指针或触摸被取消时撤销当次手势，不触发回收/完成/提交。

## 4. 时间服务与投影

时间记录使用半开区间 [startAt,endAt)，UTC 时间点负责先后和经过时长，另存输入时区与当时本地值/偏移用于历史展示。新磁吸起点按记录时区 5 分钟网格；预设时长按经过分钟相加；实际区间按分钟且 start < end。显示时区变化仅重投影，不重写记录时区和事实快照。

**生产时间适配器选用 `@js-temporal/polyfill@0.5.1`，只由 `src/action-time.ts` 导入。** 2A 再安装并锁定精确版本，不让页面依赖该库或直接用 Date.parse 消歧。本轮核对了 [官方版本记录](https://github.com/js-temporal/temporal-polyfill/releases/tag/v0.5.1)与 [TC39 时区歧义说明](https://tc39.es/proposal-temporal/docs/zoneddatetime.html)。库默认会选择歧义侧，应用须显式检查并提供选择，不能直接采用默认结果。

- resolveLocal 严格校验日期、时区与分钟输入；分别取 earlier/later 后回比本地年月日时分：无匹配即 NONEXISTENT_LOCAL_TIME，两个不同匹配即 AMBIGUOUS_LOCAL_TIME，只有用户选择合法偏移后才能提交。实际开始和结束各自独立消歧。
- 日边界按该 IANA 时区当地日期的首个有效瞬间至下一当地日期的首个有效瞬间求取；午夜跃迁日也不能加固定 24h。完全不存在的当地日期明确报错，不显示为空白可安排日。时间库依赖宿主时区数据库，升级环境后需重跑时区用例。
- DayView 携带权威 dayRange、分片、freeRanges、now、token，以及 planId/version/instanceId/instanceVersion、commitmentId/version。页面不能查询测试 fixture、默认 version=1 或另查旧 Task 来补字段。
- Segment 携带 sourceId、完整 sourceRange、当前 clippedRange、显示时区、offset、half、起止刻度、continuesBefore/After。仅切过日边界标“开始于 YYYY-MM-DD”或“续次日 →”；11:50—12:10 不标续次日，恰好次日 00:00 结束不标续次日。
- 跨午夜始终一个源对象；日/半日/偏移跃迁只拆显示。片段时长之和等于源区间与查询范围交集，完成次数按 factId 和记录时区的实际开始日期计一次；覆盖时长用并集。
- freeRanges 是“没有占用”的范围，conflicts 是安排前需确认的信息；允许重叠后不能再把“有占用”当成绝对不可保存。不能解析模板或旧时区时返回明确错误，不能把未知占用当空闲。
- 两环当作普通当地时钟视图；夏令时重复小时需显式偏移候选/列表。24 格预览条表达当地小时刻度，不声称每格在 DST 日都等于 60 分钟经过时间。该日显示 23/25 小时提示和完整带偏移列表，不能折叠两个真实时刻身份。

## 5. 持久化版本与恢复格式

冻结三个独立版本，避免把旧备份的 version=1 当作 Envelope schemaVersion：

| 层次 | 2A 目标 | 说明 |
| --- | --- | --- |
| IndexedDB | 数据库名 cardgrid-workspace；workspace/recovery 两仓库，保持当前版本 3 | 当前快照事务可满足并发；不为重复完成另建对象仓库。旧库升级事件只建缺失仓库，不运行业务迁移 |
| 本地 Envelope | schemaVersion=4；epoch、revision、mode、dataFormat、data、最小 lifecycleReceipt | mode=current 或 legacy-readonly；元数据不进业务 Data |
| 新 Data | version=2；settings、planner、legacySources、migrationBindings、commandReceipts | 空工作区不含用户记录；settings.zone 可空，设备时区仅作为待确认初值 |
| 新 Planner | version=2；definitions、instances、handOrder、plans、facts、annotations、fixed、templates、days、rules、occurrences、captures、refs、goals、history | 身份/状态按第 2 节；旧 tasks/status/blocks 只从 legacySources 读取，不形成第二个可写来源 |
| 新外部完整备份 | format=cardgrid, version=2, kind=backup, dataFormat=action-v2, data | data.version=2；不带当前 Envelope 的 epoch/revision/授权/拖动状态 |
| 新定义配置包 | format=cardgrid, version=2, kind=config, config | config 只含 settings 中可编辑偏好/分类、definitions、templates、rules；不接受实例、事实、批注、业务回执 |

settings 包含偏好、分类、明确显示时区；每个可编辑对象有递增 version。事实与批注无需可编辑版本。plannedSnapshot 保存 planId、planVersion、range 和当时内容；Data 中不存派生的自由区间、24格、显示片段、指针、日终标记或预览凭据。

支持格式清单（校验必须不重写原值；缺字段只能按该旧版本的已知可选规则解释，未知字段/歧义版本拒绝）：

| 输入 | 识别与允许动作 |
| --- | --- |
| 新 backup v2 / dataFormat=action-v2 / Data v2 | 严格校验后原样恢复为 current；Data 深度相等 |
| 旧 backup v1，data 有合法 planner.version=1 | P1A 原样恢复为 legacy-readonly；不调用 validateData 的自动补字段路径 |
| 旧 backup v1，data 无 planner，但含合法旧 config/legacyArchives 及已知旧集合 | 按该原始结构原样恢复为 legacy-readonly；缺失集合仍缺失，不自动 fromLegacy |
| 本机 Envelope schemaVersion=1 | 保留其原始 config 与完整原文，提供只读导出/显式升级；不在 load/onupgradeneeded 调 migrateV1。导出为 backup v2、dataFormat=envelope-v1、data=完整旧 Envelope；再恢复时置 legacy-readonly，data 原文深等，内含的旧 revision 仅属档案原文，不作当前提交令牌 |
| 本机 Envelope schemaVersion=2/3 | 验证 revision 与原始 data 后只读适配；不把读取结果写成 schemaVersion=4 |
| 旧 config v1 | 只支持定义/模板兼容导入预览，不冒充完整工作区恢复 |
| 非 cardgrid 的旧 version=2 days/daily/customTemplates，或 date/enabled/done JSON | 仅作为旧档案导入来源；不能声称恢复成完整 CardGrid 工作区 |
| 未知版本、损坏、缺必需字段/坏引用 | 无写入并指出路径；保留原文件和当前工作区 |

legacy-readonly 中的旧 backup v1 仍按 v1 原样导出，绝不先升级再导出；schema1 原文没有完整 Data，使用上述明确标记的 v2 封套，不伪造空集合。普通 Save/Accept/Confirm/导入定义命令在分发端统一返回 LEGACY_READ_ONLY；仅原样导出、查看、恢复、清空、显式升级可用。普通包输入沿用当前5MiB上限；schema1原文诊断导出不受输入限制，若封装文件超限则清楚标为诊断原文。所有会增加Data的正式提交与迁移预览均测算完整可恢复备份的UTF-8大小，超过5MiB返回DATA_TOO_LARGE且保留输入/原状态；防止正常写入产生本应用无法再导入的备份。调整容量上限需统一修改解析、提交和验收，不允许只放宽一端。

首次空库读取返回未初始化会话快照，不写 current。首个明确业务命令、清空或恢复才建立持久化 Envelope；旧无 epoch 记录用原始内容摘要产生稳定的读取令牌，提交在事务中对比原始内容，不能由页面临时随机 epoch 绕过并发检查。

### 精确恢复、清空与失败

1. prepareBackup 绑定当前 epoch/revision/dataFingerprint 并生成完整文件。用户确认已保存；应用只保证文件内容已生成，不假称验证了磁盘。
2. 预览恢复目标、丢弃未提交草稿范围及旧/新格式。提交前当前令牌改变则终止，重新导出/预览。
3. 一个事务替换 Data、清空全部 recovery 项（包括 previous/pre-p1a）、更新 epoch/revision 与最小生命周期回执。恢复不合并新增事实，不补集合，不追加 History。
4. 清空目标是规范空 Data v2，所有业务数组/legacySources/mappings/receipts 均空。只保留默认视觉偏好，无用户自定义时区、分类、定义、计划、事实或恢复副本。
5. 同一最近生命周期请求重试先匹配 Envelope 回执返回既有结果；后续替换使旧回执失效。回执不含旧 Data，也不为了重试重做恢复。
6. 事务中任一步失败，Data、epoch/revision、recovery 全部不变；输入与源文件仍可重试。事务完成后通知其他窗口，其他窗口恢复焦点也核对 epoch。

严格相等比较解析后的 Data，保留数组顺序及字段有无；忽略 JSON 缩进和对象键顺序。校验与规范化必须是不同函数。Web Crypto 摘要、文件读取、时间解析和下载在事务外准备；事务内使用同步的确定性比较与最终重校验，不在活跃 IndexedDB 事务中等待文件或网络。

## 6. 显式迁移与兼容

选择增量扩展当前本地执行域；不引入服务器、不重放旧事件生成事实、不使用旧 fromLegacy 的“截 Top3、暂停多余项目、忽略重复来源”等处理作为新迁移。

升级前必须有外部源备份及隔离恢复验证。PreviewMigration 返回源格式/指纹/令牌、迁移版本、逐项映射、保持原文项、必须处理问题、目标摘要；CommitMigration 比较同一来源并一次提交。真实用户数据升级须在预览可审阅后由用户明确执行，本轮仅冻结方案。

| 来源 | 目标与处理 |
| --- | --- |
| Config.Card | 新 definition，保留显式来源键和原字段快照；旧 kind 不推导抽卡权重 |
| Config.Schedule / Planner.Template | 分别保留来源命名空间；同名不合并，已被 P1A 明确导入的来源可按已存关系识别；无法证明相同则列重复候选 |
| 未完成普通 Task | open instance，保留 title/criteria/minimum/goals/projects/source/date；缺时长为 null，不猜测 |
| done Task / completed Occurrence / CardCompleted/CardReopened | 只读 legacy 原文与历史；不创建新事实、不把 completedAt 伪造成实际起止。用户要补记须显式建立带来源的新实例并确认实际 |
| 唯一有效 Task—Block 关系 | 一实例与一活动计划，保留精确旧区间；起止需用户选择的原时区消歧 |
| 一 Task 多 Block、孤立引用、重复来源、缺时区/歧义未选 | 迁移报告中的阻断项；用户逐项选择意图，未处理前不激活目标计划/实例，不任选或丢失源记录 |
| 无 Task 的固定/弹性 Block | 保留独立安排与原始种类来源，不伪造行动事实；只读兼容展示，用户显式转换后再进入新编辑流程 |
| 7 分钟等旧预设、非网格旧计划 | 原文/区间原样保留为只读兼容项；首次采用新磁吸流程须显式选择合法时长和落点，展示差异；不能自动取整或压缩 |
| Capture / Rule / Occurrence / Makeup | 保留原文、关联、日期和唯一关系；转换一次、补做一次；过去结果不改变 |
| Top3 / 项目 / Goal / Minimum Day | 原值和引用保留。超过上限或悬空引用为阻断项，不能 slice(0,3)、暗中暂停项目或删除引用 |
| 旧 History/events/legacyArchives 及所有其余字段 | 保存一份完整源快照，逐路径引用；不按相似标题或事件内容去重 |

legacySources 中每份原文有稳定 sourceId/格式/内容指纹；migrationBindings 使用 sourceId + 原集合路径 + 原 ID（Block 必带日期）作为来源键，指向新对象或只读兼容项。命名空间区分同 ID 不同来源；同来源重复升级/导入返回已有映射，同来源内容改变必须预览新差异。历史引用不能通过当前标题匹配。

只读兼容项使用 LegacyRef={kind:'legacy',sourceId,path} 引用源原文，不复制成新 Fact。Day.top3、Capture.target 允许显式 LegacyRef，校验它能解析到正确类型的源对象；新计划/事实只能引用真实新 instanceId，不能把旧done档案当行动实例。新 Instance 分别保存 occurrenceId 与 makeupOf（原例行引用或LegacyRef），校验一原例行最多一个补做实例。已转换的源路径不再额外输出兼容占用；未转换的有时间Block通过只读适配输出legacyItems并进入同一占用查询，防止双重显示与重复扣减。

迁移用户选择的原时区保存在源解释报告中，再用于旧Block转时间点；不可从当前设备时区无提示推断。旧日快照优先于当前模板；同日多模板或原时间歧义仍未解决就不提交。完整源快照、映射与目标数据同事务提交；不自动为历史done创建规则完成或新事实。

只读兼容的旧时间段仍参加占用与重叠查询，显示“旧版只读”；若时间无法解释则明确标未知并阻止该范围的自动落点推荐。不能因为它不属于新计划而显示为空闲。只读项不会进入可拖动手牌或产生新事实。最终升级提交不得有结构/身份/时区未解决的阻断项；已选择保留只读且可完整解释的非网格项可以留下待整理。

定义配置导入的“替换”只作用于可编辑目录：已被实例/事实引用的旧定义改为停用并保留历史身份；禁止删除相关实例/事实或反向覆盖快照。配置导入与完整恢复是独立命令。
