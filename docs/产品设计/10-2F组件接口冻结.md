# 2F 组件接口冻结

版本：**2F-component-1**；生效日期：2026-10-01；依据：[2C-host-1](./09-2C正式页面接口冻结.md)、[1F合同](./08-1F正式合同与阶段2边界.md)、[阶段计划](../归档/阶段0-3/产品设计/05-阶段0至3线性任务分配计划.md)。本冻结在 2E 完成 2D 页面挂载后作出，**只固化 2F 可复用组件消费的 Host 方法、命令与 props 合同，不新增任何签名、命令或字段**；所有类型以 src/action-contract.ts 生产导出为准。

2F 目标（计划行118）：可复用排期/重叠确认、撤回/固定解锁、实际确认、只读事实及批注；每个组件都有独立可验收的用户结果，完整主路径可从正式入口执行。

## 0. 跨组件共同合同（必须遵守）

- 每个组件只接受共享 `client: WorkspaceClient`（`ReturnType<typeof createWorkspaceClient>`）与生产类型；不创建第二套状态机、存储或占用/冲突算法。
- 每次 submit 的 `expected` token 取自最近一次 load/preview；通知后重新读取并重新预览，**不复用旧 previewId / acknowledgementId / unlockId**。
- revision 冲突：保留用户已填输入，重新读取并预览，不自动覆盖；epoch 改变（WORKSPACE_REPLACED）：清理旧选择、授权预览与草稿并提示。
- 提交期间禁用相关控件（busy），失败保留输入与请求，错误直接展示 Host 返回；成功/失败沿用 `.panel/.message/.primary/.toolbar` 等现有样式。
- 页面不签发凭据；重叠确认必须携带本次预览给出的 acknowledgementId；固定修改失败须重新解锁再预览。
- 缺命令或缺字段：登记缺口并回合同裁定，不在页面绕行；公开签名/命令/持久化格式/失败语义变化须用户决策并升级冻结版本。

## 1. 排期与重叠确认（PlacementDialog）

用途：把手牌实例、已有计划或已解锁固定块排到某个本地时间，并在有重叠时显式确认。

- props（冻结）：
  - `client: WorkspaceClient`
  - `subject: PlacementSubject`（`{kind:'hand',instanceId,version}` / `{kind:'plan',planId,version}` / `{kind:'fixed',commitmentId,version,unlockId}`）
  - `date: LocalDate`、`zone: string`、`initialFocusMinuteOfDay: number`（0..1435，5 的倍数）
  - `onCommitted?: (outcome: { token: Token; resultRefs: readonly EntityRef[]; replayed: boolean }) => void`、`onClose: () => void`
- 读取：`client.previewPlacement({token, subject, date, zone, focusMinuteOfDay})` → `PlacementPreview {previewId, token, query, candidates[], unresolved[]}`。
- 渲染：按 `half`（上/下半日）展示候选 `Candidate`；`state:'valid'` 可直接提交；`state:'conflict'` 展示 `blockers` 与 `reason`，必须显式确认后才允许提交。
- 提交：`submit(CommitPlacement {previewId, candidateId, acknowledgedOverlap: conflict ? acknowledgementId : null})`。
- 成功回调直接使用生产提交结果值；父组件按 `resultRefs` 重新读取权威投影：hand/plan 得到 PlanView，**fixed 只得到 fixed 引用（无计划记录）**，不得为固定块伪造 PlanView 字段。
- `unresolved`（NONEXISTENT/AMBIGUOUS_LOCAL_TIME）按 Host 给出的 message 处理，不自行造时间。
- 关闭/离页：`client.cancelPreview(previewId)` 清对应预览。

## 2. 撤回与固定解锁（FixedUnlockControl + RetractPlan）

用途：把已排计划撤回手牌；对固定块取得一次性解锁授权后调整，或放弃解锁。

- 撤回计划：`submit(RetractPlan {planId, version})`；撤回后行动回到手牌（与 2D 手牌排序/撤出衔接），有活动事实等 Host 拒绝情形直接展示。
- 固定解锁：
  - props：`client`、`commitment: VersionRef`、`target?: FixedView['range']`、`onUnlocked?: (unlockId: Id) => void`、`onClose`。
  - 按 2C-host-1 的 `client.unlockFixed(...)` 生产签名取得 `unlockId`（授权绑定对象/版本/token）。
  - 解锁后进入排期：`PlacementDialog` 的 `subject = {kind:'fixed', commitmentId, version, unlockId}`。
  - 解锁后随即 `previewPlacement`（unlock 只用于随后排期）；**放弃编辑/离页调用 `client.cancelPreview(previewId)`，它会一并释放该预览绑定的 unlockId 能力，且不写入任何数据**；cancelPreview 只接收 previewId，不得传 unlockId。
  - 若解锁后尚未建立预览（只有 unlockId）：调用 `client.invalidateCapabilities()` 清理（会清空本客户端全部能力与预览，需明确其共享影响）。
  - **`CancelFixed {commitment, unlockId}` 仅用于用户明确选择“取消这条固定安排”**（会写数据：cancelled/manuallyOverridden、版本递增，关联模板还追加当日 cancelled 例外）；关闭弹层或放弃编辑不得调用它。
  - 固定修改失败：重新解锁并重新预览，不把失败当成功。

## 3. 实际确认（ActualConfirmDialog）

用途：确认行动实际发生，生成一次事实；支持按计划或计划外（unplanned）。

- props：`client`、`instanceId: Id`、`instanceVersion: number`；计划内带 `planId/planVersion`，否则 `mode:'unplanned'`；`onConfirmed?: (fact: FactView) => void`、`onClose`。
- 输入：开始/结束本地时间（`LocalInput`），保持**分钟精度**；合同允许 `allowFutureActualEnd: true`。
- 读取：`client.previewActual({token, draft})` → `ActualPreview {previewId, token, draft, range, title, criteria, plannedRange, conflicts[], acknowledgementId}`。
- 提交：`submit(ConfirmActual {previewId, acknowledgedOverlap: acknowledgementId})`；一次行动只产生一次事实。
- 原定时间已过仍保持未确认时，可按实际区间确认；过期预览重新走 previewActual。

## 4. 只读事实与批注（FactThread）

用途：呈现已锁定事实并允许纠错性批注；事实本身只读。

- props：`client`、`facts: readonly FactView`、可选 `relatedInstance?: VersionRef`。
- 事实区**不提供**编辑、撤回或删除控件；展示实际区间、标题、来源与分钟精度。
- 批注：输入框 → `submit(AppendAnnotation {factId, text})`；批注只追加，成功后附到该事实下（`Annotation {id, factId, text, createdAt}`），失败保留输入文本。
- 双击/多窗口完成由 Host 保证只产生一次事实，组件不做本地去重计数。

## 5. 挂载与验收（2E/2F/2G 边界）

- 2E 已在 `main.tsx` 授权区段挂载 2D 页面（导航“行动定义”“抽卡手牌”），2F 组件作为这些页面内的弹层/区段复用同一 client，不新增独立顶级导航，除非后续合同另行授权。
- 2F 完成标准：自建候选 → 抽取/接受 → 手牌排序 → 打出 → 固定块冲突/无空隙 → 改期/回手牌 → 原定时间已过仍未确认 → 确认实际 → 刷新后事实不变 → 尝试修改被拒绝 → 追加批注 → 导出恢复，主路径全程从正式入口执行（对齐 G2 矩阵）。
- 2G 由与 2D—2F 分离的独立检查方按 G2 矩阵实测；本冻结不把作者自测计为外部验收。
- 2C-GAP-01/Q011在2026-10-01技术债收尾中复核闭环：生产完整区间投影及F01/F01b通过；原2C失败历史保留，接口形状不变；2F组件不在页面侧补该算法。
