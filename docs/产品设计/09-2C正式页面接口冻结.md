## 2. 唯一权威入口与冻结范围

- 入口：src/workspace-client.ts 的 createWorkspaceClient；页面接受共享 WorkspaceClient，不各自创建第二套业务状态或存储。
- 精确签名：WorkspaceClient = ReturnType<typeof createWorkspaceClient>；通用输入、命令、结果、令牌、版本及持久化字段由 src/action-contract.ts 导出。页面直接引用生产类型，不复制 docs/prototypes 类型或内存 Host。
- 格式基线：Envelope v4 / Data v2、配置包 Config v2，继续遵循1F字段合同。本次不修改格式、数据结构或事实语义。
- [冻结基线](2C-host-1-baseline.json)记录当前本地HEAD和20个受保护文件SHA256。HEAD不包含未提交实现，接手必须使用实际本地工作树。哈希用于识别实现变化，不禁止授权内部修复。

### 公开方法

| 类别 | 生产方法 | 调用约定 |
| --- | --- | --- |
| 读取与订阅 | load、readDay、readCatalog、subscribe | 读取不写业务；通知后重新读取，保留token、真实身份与版本 |
| 建议与时间 | suggest、resolveLocal | 建议不创建实例；空候选definition=null；重复时间按Host偏移选择 |
| 预览 | previewPlacement、previewInstanceUpdate、previewActual、previewDayTemplate | 消费完整区间、冲突及确认标识；页面不签发凭据 |
| 授权与取消 | unlockFixed、cancelPreview、invalidateCapabilities、close | 固定授权绑定对象/版本/token；离页清对应授权预览；只有应用所有者关闭共享客户端 |
| 配置与备份 | previewDefinitions、exportDefinitions、prepareBackup | merge/replace预览列差异；备份确认保存才形成BackupEvidence；配置提交沿用现有备份要求 |
| 生命周期 | previewRestore、previewMigration、readRecovery、exportRecovery、exportRaw | 预览及导出只读；恢复/清空/迁移走对应submit命令 |
| 旧入口适配 | readCompatibilityView | 仅临时只读视图，不用于保存 |
| 业务提交 | submit | Command → SubmitResult；普通命令不接收整份Data替换 |

业务查询、预览及导出按生产签名返回Result；subscribe返回退订函数。取消/失效/关闭和兼容视图等方法遵循各自签名，不能一律当异步Result。

### 命令与页面责任

2D使用SaveDefinition、ArchiveDefinition、AcceptOffer、ReorderHand、WithdrawInstance、ReturnWithdrawnToHand；配置JSON包走previewDefinitions → ImportDefinitions。定义表单/JSON沿用生产校验，不在页面放宽。2F使用排期、撤回、固定解锁、模板、实际确认及批注命令。所有Command的type/payload以生产类型为准，包含既有设置、Capture、Top3、例行、项目、目标命令。

- 每个业务意图生成commandId；失败保留输入及请求，重试遵循回执幂等规则。
- revision冲突保留输入、重新读取并预览，不自动覆盖；epoch改变清理旧选择、授权及草稿并提示工作区替换。
- 重叠确认提交本次预览的acknowledgementId，过期/跨预览确认不复用；页面不针对登记缺口自行补占用算法。
- 固定修改失败须重新解锁/预览；普通预览重试按Host语义处理，不能把失败当成功或自动清空表单。
- 加载、切日期、抽取建议不准备日、不占时、不生成事实；明确接受建议才创建未排期实例。
- 原事实不可编辑、撤回或删除；纠错追加批注；实际区间保留分钟精度。

## 4. 2D交接边界

下一项2D，由豆包按计划主编；本文不自动启动其他AI或开发任务。

- 页面文件：src/action-library.tsx、src/action-hand.tsx、src/components/action-card.tsx、src/action.css；页面测试按单项任务授权。
- main.tsx挂载留2E限定区段；2D不借页面开发改核心、schema、迁移、事实或存储算法。
- 交付：统一定义表单/JSON、建议/手选/重抽、接受后持有手牌、排序/撤出/返回，成功/失败反馈及刷新一致。
- 验证：接受建议不占时或完成；空候选可理解；过期版本及保存失败留输入；排序保留身份；禁用定义不再进入建议且不改已有快照。
- 缺字段/命令先登记，不建第二套状态机。公开签名、命令、持久化格式或失败语义变化须用户决策并升级冻结版本；授权内部修复可保持2C-host-1，附差异和相关回归。
