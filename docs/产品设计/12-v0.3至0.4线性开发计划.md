**最新执行决定：** 用户要求按“外部封装、内部解耦”整理现产品，并指定在新目录重建，验证后删除旧产品目录。现有代码已按 app/workshop/drawing/daily/workspace/shared 组织，公开接口与依赖检查已落地，见[模块地图](../架构/README.md)与[重建交接](../开发/2026-10-03-模块重建与迁移.md)。这覆盖“等新业务完成再整理架构”的旧顺序。W0 的新业务身份与 P01—P07 尚未裁定；持久化新功能仍等待合同确定，独立视觉验证可以先行。

基线：现产品 v0.2.0，本轮发布起点为 G3 main 提交 `2ae8ee38e5eee2d2a5c1c4b0e8ffb6227455163d`。当前模块化产品与文档归档在本提交同步，G3功能结论沿用原分离验收，重建作者回归另有记录。此前验收计数不能代替新业务版本验收。

现实现：`workspace/contracts.ts` 的 Definition/Instance/Rule/Occurrence 面向行动；Instance 已有 targetDate、定义版本与内容快照，Occurrence 指向 instanceId。书目不是一条待执行行动，新每日卡池候选也不能直接等同于已接受实例。现有正式 Host、原子保存、备份、事实不可变、跨窗口冲突与双环投影继续作为约束。新增语义需要显式合同差异和格式兼容方案，不能因为接口冻结而绕开正式写路径。

## 2. 已定产品形态

以下来自用户本轮选择，均为待实现需求：

- 制卡工坊负责原卡及生成规则。卡池按种类隔离，工作池是行动，阅读池是书目；抽取使用公共核心，内容使用各自字段。
- 原卡生成每日独立副本；副本不继续生成副本。每日生成先进入卡池，抽取并接受后才进入手牌，不自动成为待办。
- 每份副本保留来源日期，完成一份不影响其他份。旧日未完行动不自动改成今日。手牌按原卡等适当身份堆叠，显示 `×n`，展开后逐份查看；默认操作今日副本，旧份可手选。
- 工坊以整齐行列的波浪矩阵呈现牌堆封面，允许多层嵌套。进入牌堆后球面展开，卡片相对位置随整体旋转保持。
- 编辑模式露出卡面、慢速转动；抽取模式露出卡背、快速转动。进入球面后背景矩阵停波；查看单卡时球体停止，关闭后卡片归位。每次只有当前操作层成为视觉主角。
- 抽取模式每次进入重新洗位置，卡背不透露内容。第一次点击具体卡：停止并转到前方；第二次点击：翻开。此默认交互不得换成自动抽中再播放动画。
- 组合卡采用文字模板与预留位：例如“阅读《{书名}》”，书名位绑定用户预设的书目池。普通卡可没有预留位，不强制进入嵌套抽取。每个位提供单值下拉，第一项为“随机”，后续为绑定池允许的具体条目。用户已决定：主动选中“随机”后立即抽出并显示书名；选择具体条目则使用该条目。球面抽取可作为同一预留位的另一种填写入口，原两次点击规则在该入口保留。完整卡再由用户接受进手牌；文字由确定的模板合成，不引入在线大模型服务。
- 中途取消清空本次抽取草稿，不接受半成品，也不删除已有池副本。只接受最终完整组合。
- UI 保持明确主次、直觉入口，复杂功能按常用与从属关系逐层深入。代码、文档、测试分别组织成可理解的功能树。

不纳入 v0.3：饮食/消费等其他领域、AI 排程、联网同步、全面导航重建、已有事实重写。v0.4 不顺带加入新业务能力。

## 4. 两模型分工和运行规则

仅使用 **豆包 Pro** 与 **Codex GPT‑6.1 Sol**。按交付和风险分工，不以未经验证的模型能力排名作依据。

- 豆包 Pro：在冻结输入和文件边界内主编功能、单元测试、浏览器脚本及有界修复。必须提交作者自测证据，不能自行宣布外部验收。
- Codex GPT‑6.1 Sol：设计合同、审查核心差异、独立反例/浏览器复测和 Gate 判定。审查失败回给作者修复，不能默认自己重写全部代码。
- 用户：裁定产品语义、视觉取舍、真实数据操作与发布。代码重构不等于数据迁移，二者分开授权。
- 每条线各有一个修改者，使用不同分支和工作目录；公共接口变更、核心数据迁移与合入依次进行。检查针对固定快照只读运行；若需增加独立测试，单列测试写入步骤。最终检查者不得把自己的实现作为独立验收对象。
- 2026-10-03用户解除历史70%比例门槛；按模块风险、接口负责人和当前可用模型分配任务。豆包 Pro 可主编工坊/抽卡线，Codex GPT‑6.1 Sol 可主编架构/公共平台线；具体文件归属需先冻结。保留作者与检查者记录，用于质量追溯，不用于比例考核。
- 遇到额度不足：结束当前原子步骤，留任务 ID、未提交差异、实际测试结果、未满足断言、下一条操作与阻塞决定。不能把未运行写成通过。未经用户指示不自动提交、推送或真实迁移。

### v0.3 验收矩阵

1. 空工作区无需私有种子；新建行动、书目和关联规则即可跑完主路径。
2. 池种类隔离、无跨池引用混用；行动适配后能使用现有计划/实际/事实能力。
3. 原卡、每日候选、接受实例和组合来源有不同身份；跨日期完成/保存不污染其他副本。
4. 普通卡不强制抽取；预留位下拉首项随机，主动选择即得到具体词条，再次主动选择可重抽，普通重渲染/重开不触发新抽取；具体条目手选、可选球面两次点击、洗位置、取消、空池与停用来源分别验证。快速球面转动不承诺统计等概率。
5. 同时接受/生成、过期快照、刷新、存储失败与重试、跨窗口、恢复/清空，验证原子性和幂等。
6. 新旧合成备份完整恢复且字段/引用/事实不丢；真实个人迁移须用户先保存独立完整备份并授权。
7. 鼠标、键盘、小屏和低动态有等价功能证据；浏览器触控模拟与实体触屏分列，不混称已测。
8. 原有重叠确认、固定解锁、实际消歧、只读事实、批注与午夜规则复跑相关既有断言。不得删断言来过 Gate。

## 6. v0.4：按功能整理架构，保持业务行为

当前已落地的分类树；不为未来功能机械建空目录：

tests/                 # 对应功能测试、跨功能集成、独立验收

### 2026-10-03｜可选预留位选择器，覆盖旧的强制嵌套理解

已定产品语义：原卡可以写“阅读《{书名}》”等文字模板，各预留位绑定预设候选池；没有预留位的普通卡同样可使用。不强制每张卡有依赖池，也不强制抽中阅读后自动进入书目球面。用户按需要为预留位指定候选或选择随机。下拉第一项是随机，用户主动选中后立即抽出并显示一个具体书名。首项排列不表示页面加载时自动抽取。

参考：[SPICYTATER Select](https://spicytater.cn/terms/select)，参考其字段用途、单值候选、当前值与键盘操作关系；随机策略是本产品新增规则，参考页不定义本产品抽取时机。

实现边界建议：工坊负责模板/预留位/绑定池；公共选择核心返回选中条目及来源，组合器生成文字；下拉随机、下拉指定、球面选中复用同一候选与填入接口；行动模块接收完整组合结果。球面布局不进入数据模型。接受后保存具体填入值与来源快照，不能仅保存“随机”并在显示时重新抽取；原卡或池条目后续改名不自动重写已有卡或事实。确认接受仍独立于随机填入，不因选中随机就直接产生手牌。

建议初始显示“请选择书名”的占位提示，不占用候选第一项；选到随机后当前字段显示实际书名，使用户能再次主动选择随机重抽。空池不可虚构结果或跨池补选。无预留位卡直接预览完整内容；配置了预留位时能否留空、多个预留位的依赖/递归限制仍列设计待定。此记录只调整设计，不修改生产 schema。
