## 2. 三个模型的固定职责与思考强度

下表是针对本项目风险的工程分配建议，不是三个模型之间的实测排名。“Sol”在本文明确指 **GPT-6 Sol**。

| 模型与角色 | 默认强度 | 加强条件 | 主要交付 | 不承担的最终责任 |
| --- | --- | --- | --- | --- |
| GPT-6 Astra：主线 AI | `high`；常规交接检查 `medium` | 事实锁定、旧数据迁移、跨午夜状态和导入恢复冲突用 `xhigh`；`max` 只用于缩小范围后仍未解决的高风险问题 | 领域合同、核心实现、迁移/存储、架构审查、最终集成和放行 | 产品取舍最终由用户决定；不能凭模型判断替代真实浏览器证据 |
| GPT-6 Sol：开发任务 AI | `medium` | 表盘几何/输入映射、复杂交互和性质测试用 `high` | 原型、页面、组件、适配、自动化测试、局部缺陷修复 | 不自行改冻结契约、schema、存储和事实语义 |
| 豆包 Seed 2.1 Turbo：检查与资料任务 AI | `medium`；机械整理 `low` | 状态表找反例、验收矩阵审查用 `high` | 反例、fixture 草案、测试场景、交接整理、独立使用者视角检查 | 不写生产业务代码，不决定迁移或事实语义，不单独宣布发布 |

**思考档位依据**：已核对 [Astra 模型页](https://developers.openai.com/api/docs/models/gpt-6-astra)和 [Sol 模型页](https://developers.openai.com/api/docs/models/gpt-6-sol)，本计划使用的 `medium/high/xhigh/max` 是其公开 API 支持值。火山方舟[深度思考文档](https://docs.volcengine.com/docs/ark/deep-thinking?lang=zh)列出 Seed 2.1 Turbo 的思考设置；本文仅使用 `low/medium/high`。具体客户端不一定暴露所有 API 档位：若豆包界面只有“深度思考”开关，复杂审查开启、机械整理用普通模式，交接记录实际设置，不能声称精确设置了 high。模型相同也不代表各客户端拥有相同的浏览器、文件与执行工具。

### 升降档规则

- 不给所有任务统一 `xhigh/max`。先缩小任务、补齐失败证据，再决定是否升档。
- Sol 对同一问题两次针对性修复仍失败，或发现契约缺口，提交最小复现交 Astra；不用升档绕过受保护文件。
- 豆包的疑似问题先由 Sol 验证，领域语义争议交 Astra；不能为了通过测试擅自改预期。
- Astra 额度不足时暂停新的高风险任务，留下断点；Sol 可继续已冻结合同下的独立页面任务，不能自动接管未解决的迁移设计。

## 3. 编辑权、文件边界与交接

**任一时刻只有一个 AI 修改同一工作区。** 当前任务完成并交接后，下一个任务才能接手。测试同一个浏览器工作区也要串行，避免相互污染状态。本文是分配计划，不授权同时启动三个写入者。

**始终由 Astra 主线负责**：`src/domain.ts`、`src/planner.ts`、`src/planner-migration.ts`、`src/store.ts`；以及后续新增的事实记录、时间计算、可用时段、领域命令、版本迁移与备份校验模块。保护跟随职责，不因换目录名而失效。核心模块若需拆分，先由 Astra 冻结确切文件清单。

**Sol 任务范围**：交接单明确列出的页面、组件、样式、测试与隔离原型。`src/main.tsx` 是共享集成入口，每个任务必须限定具体区段；不能因为获准改 Inbox 就顺带重排配置和备份页面。`src/style.css` 同理。

**豆包任务范围**：指定文档和合成 fixture；默认只读代码。fixture 必须经真实 validator 或测试校验才能算交付通过。若其客户端不能读写仓库，产物作为文本/补丁交回，由下一个获得编辑权的 AI 核对后落盘。

`prototypes/time-dial/`与`tests/browser/`已存在；新生产模块和`src/components/hand/`、`src/components/time-dial/`尚待实现，精确边界见1F第7节。沿用既有测试工具和隔离来源，新增依赖由主线确定，不让任务AI各装一套工具。

每个任务的最小输入包：任务 ID、目标、合同版本、起始 Git 状态、允许文件、禁止文件、输入 fixture、验收标准、上次交接。每个输出包必须包含：

```text
任务 ID / 执行模型 / 实际思考设置：
起始版本与已有未提交改动：
修改文件及修改目的：
合同版本 / 受保护文件是否有差异：
实际执行的命令或浏览器步骤：
结果与证据位置（含失败、未测）：
未完成项 / 契约问题 / 阻断项：
下一任务允许修改的文件：
```

交接不能把“编写了测试”“浏览器可打开”“构建成功”写成“完整验收通过”。任务 ID 的交接记录在实际执行时再创建，不提前生成空报告。任何 AI 均不自动提交、推送或发布。
