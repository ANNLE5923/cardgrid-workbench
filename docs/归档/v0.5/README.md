## 本次改动

**新增日记能力**：独立“日记”标签，两栏（左月历、右纯文本卡片）。

- 一天一篇、纯文本，可随时续写改写；日记不是权威记录（系统归档日志才是），不套用事实/批注锁定，但存于正式工作区、走具名命令、进完整备份。
- 停顿约 1.2 秒防抖自动存；保存失败保留本地草稿、可点着重试；状态显示 已保存/保存中/失败（含 idle/dirty）。
- 跟随工作区设置时区 `settings.zone`，归属键 `(date, zone)`；可补写过去任意一天，禁止写未来；上一篇/下一篇只跳有非空文字的天，月历可逐日点选。删除规则：只能清空文字、不删记录。

**数据升级 Data v4（dataFormat action-v4）**：新增 `journalEntries` 集合与 `SaveJournalEntry` 命令，旧 v3 走“备份→预览→显式提交”迁移；新工作区直接使用 v4。v3 工坊/抽卡命令在 v4 上经适配器 `applyV3CommandOnV4` 执行。v4 是 v3 严格超集，版本门禁统一放宽为 `isV3Capable`。

## 分离验收与修复

非作者分离验收首轮结论为**暂不通过**，独立复现 3 个 P1、2 个 P2：

- P1 恢复后的工作区被旧日记草稿再次写入（epoch 污染）。
- P1 切日期/离开页面丢失尚未保存的文字（flush 不可等待、trailing 被吞）。
- P1 只浏览跨时区历史篇也会创建新记录。
- P2 打开日记的默认日期取自浏览器时区。
- P2 命令层可用另一个时区绕过未来日期保护。

作者按验收要求修复（**不改 Data v4 合同**）：

1. 保存绑定工作区 epoch，提交前重新 load 并校验 epoch；工作区被替换即废弃旧写入，旧组件无法借新 token 写入。
2. flush 返回可等待的 Promise，循环排空 trailing 到最新才 resolve；切日期须等 flush 成功，失败留在当天、保留草稿与重试；unmount 后保存循环不中断。
3. 无编辑不保存（与 baseline 比对），浏览跨时区篇不建档、已有篇未编辑不增版本。
4. 初始日期等工作区加载后按 `settings.zone` 计算；命令层未来保护改用工作区时区；切日加 `pending` 就绪态，并以 `entryKey` 区分两个空白日期，避免旧篇文字残留。
