## 2. 组件行为（与冻结对齐）

1. **PlacementDialog**（subject 为 hand/plan/fixed）：挂载与每次改“落点时间”都先 load 取新 token 再 `previewPlacement`，替换预览时 cancelPreview 旧 previewId。候选 valid 显示“这个时间没有冲突”；conflict 显示 blockers，未勾选 ack 提交报“请先勾选确认本次重叠”，勾选（“我知道有重叠，仍要安排在这个时间”）后 CommitPlacement；成功按生产结果 onCommitted（fixed 只回 fixed 引用）。关闭/离页 cancelPreview。
2. **FixedUnlockButton**：点击 `unlockFixed` 取一次性 unlockId 后回调；放弃解锁走 cancelPreview（释放能力、不写数据），CancelFixed 仅用于明确取消固定。
3. **ActualConfirmDialog**：开始/结束各有 date+time（分钟精度），编辑后置 stale；提交时若 stale 先重新 `previewActual`（runPreview 返回最新预览），有冲突须勾选，再 ConfirmActual。
4. **FactThread**：事实只读，无编辑/撤回/删除控件；每条一个批注输入，AppendAnnotation，成功刷新，失败保留文本。

**DayBoard**：初始化 load 取 settings.zone（null 则 'UTC'，不用设备时区），date 用 dateAt(now,zone) 只设一次；`readDay` 取 ProductionDayView，并从快照建 instance/fixed 标题映射。顶部控件 aria：日期/时区/默认落点。固定行取消采用“再点一次确认取消”内联确认（先 unlockFixed 再 CancelFixed）。弹层成功后关闭 + reloadDay + onChanged。

## 3. 测试中发现并修复的缺陷（组件侧）

调试浏览器主路径时发现 **ActualConfirmDialog 时间入参错误**：DayBoard 原先把 `RecordedRange.localStart`（PlainDateTime 串 `YYYY-MM-DDTHH:mm`）整体当作 `HH:mm` 传入时间输入框，导致挂载即预览失败、stale 恒为 true，弹层无法提交（界面停在“时间必须精确到分钟（HH:mm）”）。已在 day-board.tsx 新增 `splitLocal`，按 `T` 拆成 `{date:'YYYY-MM-DD', time:'HH:mm'}` 分别填入日期/时间输入；actual 弹层状态的 start/end 改为 `{date,time}`。修复后 2F-6/7/8 通过。此为组件接线 bug，未改领域命令或冻结签名。

其余调试修正（均为测试侧，未改断言强度）：①手牌页“已保存到本机”提示切到“当日”后残留，改为等待弹层关闭与具体行出现，不再依赖该全局提示；②抽卡随机且不排除已接受定义，改为抽到已持有标题就“重新抽取”，确保任务甲、任务乙各一张，并以 tab `手牌（N）` 作为接受信号；③新定义预设时长为 15 分钟，甲 09:00—09:15 与乙 09:15—09:30 仅端点相碰（intersectRanges 严格判定不算重叠），乙落点改为 09:10（09:10—09:25 真实重叠 5 分钟）。
