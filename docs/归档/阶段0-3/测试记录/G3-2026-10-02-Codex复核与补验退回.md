## 2. 补验发现（要求 / 正确性）

### R01 / P1：24:00 按钮仍预览原日 23:55

- 位置：src/components/action-flow.tsx:26—27；src/components/day-board.tsx:201—202。
- D01：09-28，默认落点23:55，+5显示24:00，点击“打出”；实际候选 **09-28T23:55—09-29T00:25**，应为 **09-29T00:00—00:30**。
- 原 B11 仅断言盘面可以显示24:00，B12仅断言手牌拖拽候选标签，未测24:00的按钮路径。
- 根因：PlacementDialog 新 snapGrid 把1440截为1435；DayBoard 没有先转换 date/minute。
- 修复方向：按 D023 在控制器做统一 landing，按钮和手势都用 nextDate + minute0；不可在弹层用23:55替代日界。

### R02 / P1：次日候选被画在原日表盘，保存后仍停原日

- 位置：src/components/day-board.tsx:181—193、279—283、301。
- D02：外环日界拖牌，候选正确为09-29T00:00—00:30；但 svg仍标09-28，日期仍09-28。点击确认后，数据确实保存到09-29，视图仍停09-28。
- 根因：候选直接叠在原 scene；onCommitted 仅 reloadDay()，未按保存日期切换。没有 originView/临时次日scene编排。
- 后果：次日候选与原日占用同屏，用户不能据盘面核对次日冲突；保存后安排不在当前列表中，造成保存反馈不一致。
- 修复方向：取得次日readDay、显示明确“原日24:00→次日00:00（未保存）”；候选只能叠在同date/zone/token场景。取消恢复原日期/读数，提交成功停在实际保存日期。D02同时保留“数据保存到正确次日”的通过子断言，不能误报存储日期错误。

### R03 / P1：切时区仍保留旧时区的可提交预览

- 位置：src/components/day-board.tsx:175—180、270。
- D03：09-28按上海09:00拖出预览，再改时区为UTC；旧调整count=1，仍显示+08:00/+08:00并可确认。
- 原 B15只测手动切日期，B17只测revision改变；时区变化不改变token。
- 修复方向：date/zone视角变化都使generation失效并cancelPreview；保留输入，按新时区显式重新预览。不能只比较epoch/revision判会话一致。

### R04 / P2：调整落点弹层没有焦点进入和 Escape 取消

- 位置：src/components/hand/HandFan.tsx:200—201。
- D04：拖牌松手后的“调整落点并确认”focusInside=false，按Escape后count=1；数据未写入。
- 原 B14只测试查看手牌弹层；ViewCardDialog用了useFlowFocus，HandFan调整仍未接。
- 修复方向：沿用 D022/useFlowFocus 或符合非模态交互的等价机制，进入弹层、Tab约束、Escape取消和关闭回触发点；拖拽盘面不能因焦点实现而被遮断。

### R05 / P1：实际盘面旋转方向与冻结公式相反

- 位置：src/components/time-dial/TimeDial.tsx:201—206。
- D05：初始09:00，从内环底部(200,294)沿顺时针90°拖到左侧(106,200)，实际读数 **12:00**；按3A rotation规则 focus'=540−2×90，应为 **06:00**。
- 原 B08只要求“与原读数不同”，错误方向也会通过；新增12项向量仅验证geometry.rotate，UI并未使用这一路径。
- 根因：每次用旋转中的当前pose反命中绝对墙钟，再把hit.totalMinute写回focus；这不是累计角差旋转，方向/接缝反馈均不等价。
- 修复方向：区分盘面旋转和候选移动，记录起始focus、指针角与累计角差，使用geometry.rotate的冻结方向/有界规则；不把命中身份当旋转角差。

### R06 / P2：已保存计划外拉松手未执行撤回

- 位置：src/components/time-dial/TimeDial.tsx:183—214；src/components/day-board.tsx:207—209。
- D06：计划弧内环半径94起拖，拉到约207（超过190且增加超过45）松手，仍status=active、handOrder=[]。
- 根因：SVG只记录旋转状态，没有已保存计划的拖动主体或RetractPlan意图；HandFan的外拉仅取消手牌预览，不能撤回已保存计划。
- 修复方向：记起始对象与半径，在有效松手时发送一次RetractPlan；pointercancel/lost capture不撤回，事实/固定/旧来源不进入此路径；保留历史与失败反馈。现有列表“撤回手牌”是替代入口，但不等于该手势已实现。

### R07 / P2：释放后的预览滑块外拉不能取消

- 位置：src/components/time-dial/TimeDial.tsx:192—214；src/components/day-board.tsx:189—193。
- D07：从已释放的候选弧开始拖，拉到约207后松手，调整count仍1，数据未写入。
- 根因：外缘没有hit时onDialPointerMove无动作，endDial只清拖动状态；HandFan此时dragCardRef已空，其reclaim逻辑不会处理候选弧。
- 修复方向：预览目标单独跟踪半径和reclaim状态；有效外拉松手cancelPreview并恢复originView，不写数据。取消双击/取消按钮的等价路径也应明确。

### R08 / P1：活动预览跨午夜仍自动换日并保留旧日候选

- 位置：src/components/day-board.tsx:79—91、40—41。
- D08：打开今日10-02，拖牌产生活动预览，推进时钟跨午夜65秒；日期自动变10-03，调整仍含10-02T12:00候选，没有跨日保持提示。
- 原 B24测试闲置今日、B25测试手动日期；没有“今日正在拖拽/预览”的分支。
- 根因：followNow仅在手动改日期/刻度时关闭，拖拽、preview、输入和dialog没有参与午夜切换条件。
- 修复方向：遵守 D024，活动输入/手势/预览时保持来源日期并提示；仅真正闲置、跟随今日的视图自动换日。任何新scene都不能叠旧日候选。

## 3. 未覆盖的静态风险与证据限度

3G.5 声称 A01—A03 已有对应自动化证据，现有套件未提供专门的hook延迟、存储失败/丢响应、固定hook重预览故障注入：

- genRef晚到保护已加入，busyRef会拒绝commit；但moveTo仍发并发请求，未做串行合并，pending仍保留旧preview/选项，HandFan确认按钮未按busy禁用。这不是完整3A pending交互。
- same-command只保留commandId，submit时重建payload；完整命令保持/变更输入后幂等处理仍需专门测试。
- fixed重新解锁顺序已改，但当前fixed UI走PlacementDialog，不是新hook的fixed路径，旧fixed按钮通过不能直接证明hook故障场景通过。
- projection-adapter仍以template-projection前缀识别模板，未按真实FixedView关联；TimeDial owned用裸item.id，跨来源同id的真实重叠可能被owner相等条件压掉。N05只验证分组数量，不验证叠色。

这些是剩余审查/补测点，不计入D八项的实测失败数量。本轮已有8个确定失败，停止扩展测试，先完成相应修复；不把未测点冒称通过。

实体触屏、真实迁移/恢复、七日使用、完整视觉偏好仍未测，本轮**不以它们拒绝G3**。拒绝依据为上述已冻结的自动化可验证行为。
