## 2. 唯一页面 Host

入口：[workspace-client.ts](../../../../app/src/workspace/client.ts)。通过 `createWorkspaceClient()` 创建；页面不直接操作 IndexedDB，不向保存接口提交整份 Data。类型由 `WorkspaceClient` 和 action-contract 导出。查询/提交返回 `Result`；订阅返回退订函数；关闭/取消方法无业务写入。

| 方法 | 输入及结果 |
| --- | --- |
| load | 当前只读快照、mode、epoch/revision；空库返回 uninitialized |
| subscribe / close | 通知后重新读取；不依赖通知携带的缓存数据 |
| readDay | date/zone → 同一快照的实例/计划/事实身份、版本、分片、freeRanges、now、occupancyKnown、legacyItems |
| readCatalog | 当前 token、定义目录、有序手牌实例 |
| suggest | token、可选分类/最低事项过滤；从合格启用定义均匀选取，空候选返回 null；不创建实例 |
| resolveLocal | date/time/zone/可选 offset；重复刻度返回两个明确偏移，缺失刻度拒绝 |
| previewPlacement | token、对象真实版本、日期/时区及五分钟落点 → 完整候选、分片、全部冲突及确认标识 |
| previewInstanceUpdate | token、instance、content、targetDate、start → 活动计划修改的完整区间与冲突；绑定编辑内容 |
| previewActual | token、独立起止 LocalInput、实例及可选计划版本 → 实际记录预览 |
| previewDayTemplate | token、date、zone、templateId、可选 entryOffsets → 日期/固定条目变化、全部冲突；保留手动例外 |
| unlockFixed / cancelPreview / invalidateCapabilities | 固定授权绑定单对象/版本/token；取消、导航、重载、令牌变化和一次提交结果使其失效 |
| prepareBackup | 生成准确文件文本、token、Data 摘要；用户确认已保存后才能作为 BackupEvidence 使用 |
| previewRestore | token、完整备份文本 → 格式和替换目标；预览无写入 |
| previewMigration | token、原时区/逐路径只读选择/起止偏移、可选来源 → 映射、阻断项、目标摘要 |
| previewDefinitions | token、配置包文本、merge/replace → 数量、停用项与逐对象前后差异 |
| exportDefinitions / readRecovery / exportRecovery / exportRaw | 可移植定义包、恢复点列表、可恢复备份包及诊断原文；读取无写入 |
| readCompatibilityView | 给旧组件生成临时只读模型，绝不用于保存 |
| submit | `Command` → 当前 token、resultRefs、是否重放；没有直接替换 Data 的普通命令 |

正式命令包括冻结合同的 SaveDefinition、ArchiveDefinition、AcceptOffer、ResolveCaptureToAction、UpdateOpenInstance、ReorderHand、WithdrawInstance、ReturnWithdrawnToHand、CommitPlacement、RetractPlan、CancelFixed、ApplyDayTemplate、ConfirmActual、AppendAnnotation、PrepareDay、CreateMakeup、ImportDefinitions、RestoreWorkspace、ClearWorkspace、CommitMigration。

为既有受保护功能补充 SaveSettings、CreateCapture、SetCaptureStatus、UpdateDay（Top3/Minimum Day）、SaveTemplate、SaveRule、SaveProject、SaveGoal。对应设置历史使用 `EntityRef {kind:'settings', id:'workspace'}`；这是 1F 要求补齐的受保护命令适配，不另建第二份业务状态。

### 使用约定

- 每个业务意图生成一个 commandId；存储失败保留请求及输入。成功重试先返回原回执，不再次执行。
- 普通确认/排期存储失败保留可重试的预览；固定修改失败结束解锁，需重新解锁/预览，仍可保留业务请求 ID。
- 跨 epoch 提交拒绝；页面清除旧选择、授权和草稿。仅 revision 改变时保留输入，但要求重新读取，不自动覆盖。
- PrepareDay 可重复调用，同 rule/date 不重复生成；读取不把过去 generated 写为 missed。旧 occurrence 已有日期不会通过新规则再生成。
- 模板消歧通过 entryOffsets 逐条提供，不自动取 earlier/later。过去普通计划可调整，过去原例行通过独立补做处理。

## 4. 数据与迁移要点

- 恢复比较解析后的 Data，保留数组顺序和字段有无。新版精确恢复不追加 History；旧 backup v1 继续按 v1 原样导出。schema 1 用 envelope-v1 完整原文封套。
- 清空目标是规范空 Data，所有用户数组、来源、映射及业务回执为空；新 epoch 的最小生命周期回执仅在 Envelope。
- Web Crypto 摘要在事务外计算；事务内同步比较原文与 token、重查回执及不变量，一次提交工作区和 recovery。
- 所有增加 Data 的提交及迁移预览检查完整备份 UTF-8 的 5 MiB 限额；下载采用同一紧凑序列化，避免缩进使“可写”数据变成不可导入文件。
- 来源路径以集合原 ID 定位，例如 `/planner/days/@2026-09-27/blocks/@b`。sourceId+路径隔离命名空间；SHA-256 检查原文身份。无原始条目标识的旧日模板占用引用该原日快照，以独立展示 ID 区分时段。
- 原文不修改；时区/选择解释保存在 MigrationCommitted.after。迁移历史绑定真正的提交 commandId 和提交时间。
- 旧 done/completed/历史不生成事实；唯一合法 Task—Block 转一个实例和计划；多块关联/未解释时区等阻断，非网格区间保留只读且计入占用。
- 旧 Capture、Top3、Minimum Day、项目/目标、规则和补做关系保留。新旧重复补做返回已有关系；不改原例行日期/结果。
- 旧非网格 config v1 不会被自动取整；可通过完整来源迁移保留只读，或由用户明确修改配置后重新预览。
- 未知格式/坏引用/源摘要不一致拒绝读写并允许导出诊断原文；未知旧占用通过 occupancyKnown 明示，不当成空闲。
