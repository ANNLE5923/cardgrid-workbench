## 二、测试环境与隔离要求

### 2.1 环境要求

- 浏览器：Chrome 或 Chromium 最新稳定版，需支持 IndexedDB、BroadcastChannel、`<dialog>`。
- 运行方式：`npm run dev`（http://127.0.0.1:4173/）或 `npm run preview`（生产构建后）。
- 多窗口测试：同一浏览器开两个标签页（tab），不使用两个不同浏览器（IndexedDB 不跨浏览器共享）。
- 测试数据：仅使用下方第三节定义的合成 fixture，不得导入真实用户数据。

### 2.2 隔离要求（强制执行）

1. **每个测试场景开始前，必须清空测试工作区的 IndexedDB**：
   - 浏览器控制台执行：`indexedDB.deleteDatabase('cardgrid-workspace')`，然后刷新页面。
   - 或使用数据与备份页面的"清空工作台"（需输入"清空"确认，会自动下载清空前备份——该备份仅用于测试，不得覆盖真实备份）。
2. **不得在用户真实使用的浏览器配置文件中执行测试**。建议使用 Chrome 的 `--user-data-dir` 指定临时目录，或使用浏览器的"访客模式"。
3. **测试产生的备份文件保存到临时目录**，测试结束后删除，不得与用户真实备份混放。
4. **真实数据迁移前必须有独立外部备份**：本矩阵不涉及真实数据迁移。若后续要迁移真实数据，必须先让用户在正常使用的浏览器中导出完整备份并保存到外部位置，且已验证恢复路径。

### 2.3 数据比较工具

所有"数据比较方式"均使用以下方法之一：

- **方法 D1（完整深度比较）**：导出备份 JSON，与预期数据做 `JSON.stringify` 后逐字段比较。忽略 `revision`、`history[].at`、`captures[].at`、`legacyArchives[].importedAt` 等时间戳字段。
- **方法 D2（关键字段抽样）**：通过浏览器控制台 `await store.load()` 读取当前 Envelope，检查具体字段值（如 `planner.tasks.length`、`planner.captures[0].status`、`planner.days.find(d=>d.date==='...').blocks.length`）。
- **方法 D3（页面显示验证）**：刷新页面后，检查 Today/Inbox/Schedule 页面显示的内容与预期一致。
- **方法 D4（IndexedDB 直接读取）**：通过浏览器控制台直接读取 IndexedDB 的 workspace/current 和 recovery/previous、recovery/pre-p1a，验证原始存储内容。

### 8.1 未具备条件

| 条件 | 影响场景 | 说明 |
|---|---|---|
| schemaVersion===1 旧版数据 | A06 | 需构造旧版数据才能验证 pre-p1a 恢复点真实升级路径。代码已静态审查，运行时验证待补。 |

| 离线模式 | — | PWA 离线可用不在本矩阵范围（属 F03/后续）。 |

### 8.2 风险与注意事项

1. **BroadcastChannel 仅在同源同浏览器的标签页间工作**：不要用两个不同浏览器测多窗口冲突。
2. **清空工作台会自动下载备份**：测试时注意区分"清空前备份"和"完整备份"，不要混淆。
3. **revision 冲突是制造保存失败的主要方式**：确保 Tab A 在 Tab B 修改后不重新载入，直接操作即可触发。
4. **bootstrap 会在页面加载时自动运行**：清空后刷新可能生成当天 day（如果模板 weekdays 匹配测试日期），验证"空白"时需注意这一点。
5. **测试结束后必须清理**：删除测试产生的备份文件，关闭测试标签页，避免影响用户正常使用。
