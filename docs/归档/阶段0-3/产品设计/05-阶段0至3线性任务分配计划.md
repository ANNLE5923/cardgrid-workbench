## 2. 从2B起的任务主编、设计责任与模型选择

**历史执行记录保留原貌。** 从本次修订后新启动的开发任务起，豆包主编至少70%的已验收开发任务；Codex优先用于开工前发现系统设计缺陷、冻结边界、审查高风险差异和放行。编写核心模块可交豆包，但系统合同、事实不可变、精确恢复/清空和数据迁移语义须先由Codex审查。用户决定产品取舍。

**计数规则**：一个开发任务须有独立目标、限定文件和可核查的代码或自动化验证交付；任务拆分须对应真实接口或用户行为。仅按被接受的任务计数，草案、失败任务、纯整理、Codex复核与Gate判断均不算开发交付；若Codex重写主要实现，该项计Codex主编。每累计10项已验收的新开发任务至少7项由豆包主编，不足10项时按向上取整保持70%；同时记录Codex复核耗时与返工，不能靠碎分任务满足比例却耗尽Codex额度。若要临时破例，先在任务交接记录说明原因和补偿安排，不降低数据门槛。

| 角色 | 默认任务 | 升级与边界 |
| --- | --- | --- |
| 豆包 Seed 2.1 Pro · 高推理 | 2B后有明确合同的核心修复、格式/时间/事务/恢复相关实现、正式Host集成、复杂表盘手势 | 高风险文件须先定输入输出和失败语义，写后给最小复现及隔离数据证据；不得自行改事实或迁移规则 |
| 豆包 Seed 2.1 Turbo · 按客户端实际可用设置 | 冻结接口后的页面、普通组件、独立回归与布局调整 | 首次用短任务确认实际可运行；复杂跨文件问题升Pro，不凭模型名称假定能力或工具权限 |
| 豆包 Seed 2.1 Lite · 按客户端实际可用设置 | 边界明确的样式、文案、简单组件与合成fixture | 只有实际代码/验证交付才能计入开发任务；不能用资料任务凑70% |
| Codex · 设计与审查 | 每项的合同和验收条件，核心差异审查，2C/G2/3A/G3关口与产品风险回交 | 可做紧急有界修复，但该开发任务按Codex主编计数；不以自测代替独立验收 |

固定记录客户端实际选用的模型和推理档位，避免“自动”切换造成结果不可追踪。截图中Turbo可选，但可用性以实际运行确认；具体界面的档位也以执行记录为准。相同模型的不同会话可互查，关键事实/恢复/事务仍需Codex独立审查。若豆包客户端不能直接读写同一仓库并运行必要检查，先做能力验证；只交文本补丁时，须由接手人核对应用并验证后才可算完成，返工重写按实际主编计。

## 3. 编辑权、文件边界与交接

**任一时刻只有一个 AI 修改同一工作区。** 当前任务完成并交接后，下一个任务才能接手。测试同一个浏览器工作区也要串行，避免相互污染状态。本文是分配计划，不授权同时启动三个写入者。

**Codex拥有设计与放行责任，豆包可拥有实现编辑权。** 每张任务卡写明唯一主编、允许文件、禁止文件、冻结接口、失败语义和复核人。`src/domain.ts`、`src/planner.ts`、`src/planner-migration.ts`、`src/store.ts`、`src/main.tsx`及新的action/workspace核心模块均属高风险文件；豆包Pro可以按单项授权编辑，Codex先审合同、后审差异和证据。`src/main.tsx`与`src/style.css`须限定区段，不因编辑一页顺带重排其他功能。任务授权不等于允许修改schema或事实语义。

当前本地有未提交的2A核心、2B测试、原型和文档；远端`main`仅有此前的规划提交。豆包接手必须以**实际本地工作树和当前差异清单**为输入，先记录基线，不能从旧远端HEAD重新开发或覆盖已有改动。若使用另一客户端/目录，先确认它能读取同一版本、运行命令并回交修改；不能将未同步的1F合同或2A源码当作远端已有。

`prototypes/time-dial/`与`tests/browser/`已存在；新生产模块和`src/components/hand/`、`src/components/time-dial/`尚待实现，精确边界见1F第7节。沿用既有测试工具和隔离来源，新增依赖由主线确定，不让任务AI各装一套工具。

每个任务的最小输入包：任务 ID、目标、合同版本、起始 Git 状态、允许文件、禁止文件、输入 fixture、验收标准、上次交接。每个输出包必须包含：

```text

起始版本与已有未提交改动：
主编与复核人 / 是否计入70%开发任务：
修改文件及修改目的：
合同版本 / 受保护文件是否有差异：
实际执行的命令或浏览器步骤：
结果与证据位置（含失败、未测）：
未完成项 / 契约问题 / 阻断项：

```

交接不能把“编写了测试”“浏览器可打开”“构建成功”写成“完整验收通过”。任务 ID 的交接记录在实际执行时再创建，不提前生成空报告。任何 AI 均不自动提交、推送或发布。
