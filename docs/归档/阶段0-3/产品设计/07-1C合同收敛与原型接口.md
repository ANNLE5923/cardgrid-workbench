## 1. 审查结论与证据纠正

1B 实际包含 **24 个 R 条目、19 行既有 C 用例复查、6 个新增用例建议、15 个 M 汇总条目**；M 与 R 是同一批问题的不同视图，不重复计算缺陷。原报告末尾的数量不准确，保留原文供追溯。全部是静态审查，不能据此宣称新行为已通过浏览器验收。

- **并发问题需要原子校验，但不要求为当前快照架构新增事实索引。** `src/store.ts:17–21` 已在覆盖 workspace/recovery 的同一个读写事务中读取当前值、比较 revision 并写回。重叠作用域的 IndexedDB 读写事务不能同时执行；后启动的事务看到前一事务结果，见 [W3C 事务调度规范](https://www.w3.org/TR/IndexedDB/#transaction-scheduling)。1B 的“两个事务都读到旧值”推断不适用于这条路径。2A 仍须在最终提交边界校验每实例至多一事实、Capture 至多一次转换；按钮禁用无效替代。是否拆分对象仓库/设置索引留给 1F，不能为一个错误前提改变架构。
- **`store.commit` 没有自动追加 History。** 它保存恢复点与快照；历史来自领域函数。1A 已禁止恢复追加业务历史，也已要求只读加载。真实差距是 `main.reload → importDefinitions/bootstrap` 和当前校验/升级路径会规范化或生成数据，2A 必须消除这些隐式写入，不能把它们当作 1C 已修好的代码。
- **时间点加预设分钟用毫秒加法是正确的。** 不能固定加 24 小时的是“求下一当地日期零点”。纽约 2026-10-31 23:00 -04:00 对应 11-01 03:00Z；加 150 分钟得到 01:30 -04:00，加 210 分钟得到 01:30 -05:00。1B 把转换日、重复时刻与时长运算混淆。已用 Node/Intl 核对以上结果；尚未实现时区解析服务。
- **错误事实仍按 D008 永久锁定。** 不采纳“误录可撤销窗口”的建议，不重新要求用户确认已作出的决定。改进确认前的内容/日期/时区展示，确认后仅追加说明。
- 当前应用没有 HTTP 后端；重试场景应描述为本地事务已完成但回调/UI 丢失、窗口关闭或重复点击。当前备份包是 `format=cardgrid, version=1, kind=backup, data`，并不携带本地 Envelope 的 schemaVersion。旧格式识别必须依真实包结构，不能直接照抄 1B 的 schemaVersion=2 示例。

## 3. 补充提交、恢复与时间合同

### 3.1 提交与失败

普通命令顺序：检查 epoch → 匹配同 commandId/输入指纹的成功回执 → 核对 revision → 在当前快照验证命令及关系约束 → 同事务提交 Data/History/回执。相同 commandId 不同业务内容拒绝。已成功命令重试不再创造对象，返回原引用及当前快照/令牌；已确认的事实详情可在冲突后重新加载取得。

重叠凭据绑定 epoch、revision、完整确认输入和冲突集合；无独立超时。每次提交重新计算冲突；修改输入、任何工作区写入或生命周期替换后失效。planned 确认只排除自身将封存的活动计划；unplanned 确认不能拿一个无关 planId 来绕过冲突。确认成功即永久锁定，不因批注或定义更新改写。

同一 ruleId/date 的 PrepareDay、同一原 occurrenceId 的 CreateMakeup 为业务幂等：相同命令重试返回回执；不同命令使用最新修订仍返回现有对象而不重复。过期修订先拒绝，不擅自合并。Capture 不同命令重复转换返回已转换对象信息及 CAPTURE_ALREADY_RESOLVED，不再新建。

### 3.2 生命周期边界

操作前展示当前未保存输入将被放弃，备份不含未提交草稿。生命周期**成功后**清除旧草稿、拖拽/选中、重叠凭据及固定块授权；收到替换通知的其他窗口同样失效并加载新工作区。睡眠/离线窗口恢复焦点时重新核对 epoch；提交端仍拒绝旧 epoch。不能承诺瞬时擦除已暂停进程的内存，但不得把旧事实/草稿另存为本机隐藏恢复副本。操作失败不清除输入和当前数据。

备份准备结果绑定 `{epoch, revision, dataFingerprint}`；这是应用已生成所需文件的证据，不等于浏览器已证明用户磁盘写入成功。界面明确要求用户确认文件已保存。恢复/清空提交比较同一源令牌，不匹配则终止并重新导出/确认，不能覆盖期间新增的数据。

严格恢复相等指解析后的 Data 深度相等，保留数组顺序、数值与字段有无；不要求 JSON 缩进/键顺序或外层导出时间戳字节相等。不添加业务历史/默认集合/例行。Envelope 的存储元数据可改变，不含旧业务副本。生命周期最小回执仅保证最近一次替换的相同请求可识别；后续再次替换后旧请求返回 WORKSPACE_REPLACED，不能为识别重试再执行一次。清空时所有本机恢复点一并删除。

支持的旧格式原样保存为当前 raw Data，legacy-readonly 的适配结果只在内存中用于查看，不写回补字段。普通命令在 dispatcher 拒绝 LEGACY_READ_ONLY；显式升级是另一个带预览、备份与原子提交的命令。1F 列清受支持包格式与检测规则；未知/歧义格式拒绝。当前自动升级路径不满足此合同，不能复用后声称完成。

### 3.3 时间、模板与历史

用户在 1C 已决定 D016/D017：允许提前确认未来结束时间，仍保存独立 confirmedAt 并立即锁定；确认页突出显示未来结束提示。只有非法日期、起止倒置、歧义未消除等输入错误会拒绝，不能返回 FUTURE_ACTUAL_END。日终按工作区显示时区的下一当地零点判断，now 到达日范围 endAt 后自动填红；关闭应用无后台任务，下次读取直接派生。确认后原计划仅为对照，实际区间参与占用；红色随当前记录重新计算，不储存结束标记或空时间事实。切换显示时区按明确选择重算日边界，不改既有时间点。

预设时长是经过分钟数，结束点由确定起点加分钟得到。5 分钟网格校验基于记录时区当地起点；对秋季重复刻度给两个带偏移的候选，对春季不存在刻度给错误。跨日显示不能加事实、重复计数或切断源区间。连续可用性只看当前有效占用：历史上占过、现已释放的相邻空隙可以连成完整空段。

模板应用的预览要逐项列出新增、更新、移除及保留原因。候选方案：仅原模板管理且未有当天覆盖的块可替换；手动例外/手动固定块/活动卡牌/事实保持。以替换后的完整结果检查新增或改变的占用；已存在的事实重叠不因无改动而使操作失败。遇新冲突整次拒绝并列明对象，由用户先处理；“跳过部分块”若未来需要，必须另做明确差异预览，不能静默发生。未物化模板的只读投影与提交校验读取同一版本来源，不能预览算空、提交突然生成另一个模板。

## 5. 原型接口冻结：1C-prototype-1

机器可检查的接口：[1C-prototype-contract.ts](../../../产品设计/1C-prototype-contract.ts)。这是展示/模拟边界，不是持久化 schema；1D 只能消费或实现模拟适配器，不能导入生产 store/迁移函数。对象 ID 在合成场景内稳定，时间服务输出为权威结果，组件不再自行判断空闲或生成事实。

### 5.1 输入与投影

- Host 持有唯一内存状态，返回 token 与不可变视图。日期/时区、完整占用、显示分片、文字标签和候选由 Host 产生；列表与时间盘共用同一投影。缺时区、无效日期及时间歧义返回明确失败，不能当空白日。
- 几何以 12 点为 0°、顺时针为正；两环分别表达 00:00–12:00 / 12:00–24:00，当地分钟模 720 映射为 `minute / 720 * 360°`。基准 inner=前十二小时、outer=后十二小时，标签始终可见；1D 可提供显式交换环位置的对照，不改变候选身份。
- “面向用户”原型编辑轴为 6 点方向（180°）。旋转偏移为 `180 - focusMinuteOfDay / 720 * 360`；范围 0–1440，对应最多两圈且不绕回。顺时针拖盘向更早时间，逆时针向更晚时间。两环、全部滑块与数字刻度同转，指针固定；命中坐标须逆变换。初次读数取 Host 的 now，24:00 只作当天终点，不可作为新安排起点。
- 点牌转正、放大为独立查看浮窗，其他牌保持原位；再次上推浮窗，才在指针指向的**一个绝对时间**吸附为完整区间的连续弧形滑块，释放只进入预览。按住滑块只改滑块落点，盘与指针保持不动；沿圆周按 5 分钟磁吸，径向可换半日。跨午夜结束点可在次日，必须查询次日重叠对象。
- 候选携带 ID、日期、时区/偏移、完整区间、版本令牌。只有夏令时重复当地刻度才可能在同一绝对表盘读数产生多个偏移身份，必须逐个明确选择；不存在的当地刻度不可打出。
- 普通分片按日/半日裁剪；遇时区偏移跃迁需另外拆段，不能输出终点角度小于起点的伪负时长线段。DST 无法清楚环形表示时，以带偏移及经过时长的列表作为完整表达，不把完整记录截短。
- 卡牌上缘变形成候选完整区间的连续弧段，跨环/跨日则多显示片段但仍一个候选。占用也按完整区间显示为连续段，交叉部分叠色；5 分钟只是吸附步长，15/25 分钟是连续 3/5 单位。左侧预览条有 24 格，每格一小时；左箭头指 now 且可点击复位，右箭头指固定指针的读数。指针扫到的所有重叠项目共同轻微放大，并全部进入“当前选择”列表。
- 重叠候选列出对象和交叉区间，明确二次确认后可保存；凭据绑定预览、候选、版本与冲突集合，提交时重新核对。已有事实不因重叠被改写。取消/指针丢失/切日期/外部版本变化使预览失效，回到未提交状态。不存在的当地时刻仍拒绝；成功提交后才从手牌移除，存储失败保持原状态。

### 5.2 手牌、键盘与风格

固定牌堆点开后，卡牌悬浮于页面上方，在下半屏围绕共用、位于屏外的支点按固定角度分布，不出现底部方框容器。选中牌转正并放大为独立浮窗，其他卡 transform/位置不变；不因选择重新均分角度。多牌超出可操作宽度时提供页/列表切换而非缩成无法点中的缝。展开/收拢/选中不调用 submit。

键盘等价：选择牌 → 浮窗按钮进入安排 → 调滑块 5 分钟 → 必要时选择带偏移的候选 → 核对重叠并确认，Escape 取消；Tab 可到达所有必要按钮。查看与安排按钮分开，按 Enter 查看不能直接打出。事实无拖动入口；固定块移动须显式解锁，若新位置重叠仍须另行确认。

按 DESIGN.md 使用任务标题/导航/就近命令及连续表面，保留纸色/绿基调；日终红色有“空时间”图例，危险操作有独立图标和文字。浅色/夜间、可见焦点、4px 节奏、720/390/320px 都需查看。原生滚动优先；原生无阻尼的平台可在原型内做有限距离的边缘回弹，松手归位，不能挤占拖牌/转盘手势；reduced-motion 取消弹性/扇形过渡，仍保留状态和所有操作。参数由 1D 通过实际体验记录，不由 1C 虚构最优值。
