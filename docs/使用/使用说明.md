# CardGrid · 卡格工作台

CardGrid 是一个以 Today 为入口的本地优先个人工作台，帮助你把每天的安排、临时想法和行动放在同一处，并看清计划如何变成实际执行。

## v0.6 通用框架（2026-10-07，未发布集成）

main 未提交工作树已接入通用框架；发布版本仍为 v0.5.0，剩余验收见[主线收尾](../开发/2026-10-06-v0.6并行开发计划.md#23-主线集成与整体收尾2026-10-07)。空白工作区不预装个人卡包。

1. 在“工坊”建资源牌堆和条目，即可维护独立清单，无须绑定行动、决策或生成规则。条目可跨同类牌堆移动，网址按钮只记录 CardGrid 发起的打开操作。
2. 行动可以直接从工坊拿取，也可在“抽卡与决策”勾选行动牌堆后从球面翻牌或手选。决策问题提供指定清单中的具体答案；重渲染和切页保留已选答案，主动重抽才换结果。
3. 在三槽合成台选一张本次行动／中间成品和一张本次答案，查看成品并确认。只消耗指定的两份素材，原卡和原库保留；归属不一致或已安排素材会明确拒绝。
4. 右下角手牌跨页存在，只有 Today 可打出。行动成为安排，再明确确认实际；答案默认贴附已有行动共用安排，也可作独立零分钟参考，不自动创造事实。
5. “时间线日记”的自动段来自表盘，独立感想按条保存。移动或收回安排改变自动段，收回不删感想。编辑感想保留原记录时间并显示“修改于”；睡眠来自已有安排／日型模板，旧日记全文单独保留。切日、离页会先保存草稿，失败时停留并保留输入。

“备份与恢复”提供三领域＋独立清单的通用配置示例和 AI 配置说明。导入需先预览并保存当前活动 JSON 及所需 ZIP；稳定 ID 表示更新，重复包不会额外创建材料。不合法引用、未知字段或超额配置整包拒绝。

主数据“已保存到本机”和文本文件“已同步”是两种状态。在日记页连接目录后，日记和维护日志使用同一个单向写入器生成逐日 `.md`／`.txt`。主数据成功而文件失败时，继续保留主数据及待写状态，重新授权或补写即可；不支持目录授权／写锁的浏览器可手动下载文本。

外部修改在下一次写入、重连或主动刷新时处理：先保留外部原字节副本，恢复最后成功输出，再写最新内容。副本、关闭或字节核验失败时暂停覆盖并提示。不会持续监控、把外部文件导回或回滚工作区；换工作区后旧任务暂停，原文件保留。

月度提醒只提示，不自动删除。封存月份先预览保留／移出范围，下载 ZIP，再重新选择实际外部文件验证；最后另行明确确认移出。未完成及跨月依赖按闭包保留，失败时原库不变。多个 ZIP 可同时导入只读浏览，按包解码，切换／关闭释放上一包；外来包不并入活动工作区。已封存日不能新建安排或改写旧正文；活动区保留的未完成安排仍可移到活动日或收回。

**完整历史恢复需要活动 JSON 和它列出的归档 ZIP。** 缺包时活动数据仍可恢复，历史显示不完整且不覆盖原历史文件；补齐匹配 ZIP 后恢复历史可读性。维护日志独立备份，不在业务／日记主包中。32／64 MiB 是字节门槛，不是任意设备内存保证。

旧 Data2/3/4 继续使用原入口，备份按原格式精确恢复。Data4 只有“下载完整备份 → 确认已保存 → 预览并确认升级”才变成 Data5。升级后的入口是 Today、工坊、抽卡与决策、时间线日记、维护日志、备份与恢复；旧 Inbox、定义及项目数据保留，但这些独立页面尚未接入新壳。需要继续使用时可精确恢复升级前备份，恢复前先备份当前数据。

## 为什么做？

日程在日历里、待办在任务软件里、想法在笔记里；每天开始时，人仍要自己回答“今天该做什么”。CardGrid 从这个问题出发：先看今天，再调整安排并采取行动。它面向想自行管理时间和任务的个人用户，不以团队协作为当前目标。更完整的方向见[项目定位与 README 规范](../项目定位说明.md)。

## 核心特点

- **Today 优先**：先理解今天的安排和重点，再决定下一步行动。
- **从空白开始，自主配置**：自己建立日型、星期安排和卡片定义。
- **先捕获，再整理**：临时想法进入 Inbox，不会自动变成当天任务。
- **区分安排与变化**：当天调整不必改写长期日型模板。
- **本地优先**：无需账号，工作数据保存在当前浏览器，由你导出备份。

## v0.5 已发布功能与兼容基线

### Today

默认显示正式双环时间盘和手牌，可直接排期、改期、撤回、确认分钟精度实际区间并追加事实批注，也可快速记录想法。点击“去抽卡”，明确接受后点击“返回 Today 安排”，继续在原浏览日期、时区与手动落点安排。首次打开为空白工作台；旧格式保留只读兼容查看。

### Inbox

保存快速记录，捕获时不必填写日期、优先级和项目；旧记录以兼容视图展示。

### Schedule

查看完整安排，显式准备日型；模板可通过统一配置 JSON 编辑。固定块解锁与调整、计划撤回在 Today 完成。

### 行动定义与抽卡手牌

自建定义、抽取/重抽/手选、排序手牌。“当日”快捷入口返回 Today，其正式双环时间盘和可拖动手牌支持5分钟落点、改期与外拉撤回；所有操作都有按钮或表单路径。重叠须确认，固定修改须解锁；已确认事实只读，可追加批注。

### 制卡工坊与每日库存（v0.3）

先建书目，在“卡池”建立书目池并勾选成员；再建行动原卡，例如 `阅读《{书名}》`，添加标签为“书名”的槽位并绑定该池。每张卡的槽位标签必须不同。无槽普通行动也可直接使用。

在“生成规则”选择原卡，设置每日/指定星期、开始日期与时区。进入抽卡手牌会协调今日库存。球面第一下选中具体卡，第二下翻开；也可直接手选副本。槽位下拉的第一个可选项“随机”立即固定书目，只有你主动再选随机才重抽。检查组合文字后接受，再到“当日”排期或记录实际。

槽位下拉最多十项：必填槽“随机”＋最多九本书；可选槽另有“留空”，最多八本书。候选较多时随机展示一组，同次查看保持稳定。“随机”与球面选择覆盖完整池，已选书名始终保留在菜单中。

每个新建／修改后的卡池或牌堆最多 100 个直接成员，库存、手牌和历史不设总量上限。满池时移出一张才能加入新成员；表单、JSON 和配置导入均检查容量。本轮不会自动清理已有个人数据，完整备份仍可精确恢复；超限配置包需满足上限后才能导入／导出。

手牌 `×n` 是多份独立行动，展开后逐份操作并查看来源日。副本在来源日 D 至 D+6 保留，D+7 起归档并撤销未完成排期；接受、改期不延长来源期限。事实和批注保留在“归档日志”。同一天有意再次接受会新增独立行动；保存失败的“重试本次保存”只确认原命令，不重复创建。

关闭期间不后台生成；启动、回到可见状态与可见页面规则时区午夜进行协调。只自动生成当前日，漏日可从“手动补生成漏日”选择规则和来源日期补回。未来、超出保留期或没有当日版本证据的日期会拒绝。小屏/减少动态效果默认静止列表，两步翻牌规则相同。

## 开始使用

需要 **Node.js 22.18+（22.x）或24+**。先下载源码，或克隆仓库后进入项目目录：

```sh
git clone https://github.com/ANNLE5923/cardgrid-workbench.git
cd cardgrid-workbench
```

然后运行（应用位于 `app/`）：

```sh
cd app
npm ci
npm run dev
```

然后在本机浏览器打开 <http://127.0.0.1:4173/>。Windows 用户也可以双击 [scripts/启动卡格工作台.bat](../../app/scripts/启动卡格工作台.bat)。开发服务器只监听本机回环地址，局域网设备无法直接访问；关闭服务器窗口即可停止。

首次使用可在“行动定义”创建一条定义，点击“加入手牌（手选）”，再到“抽卡手牌 → 当日”安排并确认实际。重复日型在配置 JSON 中编辑，在 Schedule 显式准备；查看或切日期不会自动生成安排。

## 数据与隐私

- 无需账号。数据保存在当前浏览器的 IndexedDB，应用不会主动将工作区数据上传到服务器。
- 数据按浏览器来源和用户配置隔离；换浏览器、设备或端口，或清除站点数据，可能看到另一空白工作区或失去本机数据。
- 定期从“数据与备份”下载完整备份，并妥善保管。备份可能含有私人日程和记录，请勿随源码公开。
- IndexedDB 不是加密保险箱；能访问本机浏览器配置文件的人可能读取其中数据。
- 离线缓存只包含应用文件，不缓存工作区数据。

### 从旧版本升级

旧备份按原 Data v2 精确恢复，日常排期仍可使用。新工坊需要 Data v3：进入“数据与备份”，下载完整备份并确认文件已保存，预览升级内容，再明确执行升级。读取旧工作区不会自动升级。ConfigV3 只含配置与工坊目录，不能替代含库存、手牌、事实和日志的完整 BackupV3。

## 开发说明

[文档入口](../README.md)汇总当前设计、正式合同和[已完成开发归档](../归档/阶段0-3/README.md)。

应用使用 React、TypeScript 和 Vite；工作数据保存在浏览器 IndexedDB 中。源码按 `app/`、`workshop/`、`drawing/`、`daily/`、`workspace/`、`shared/` 组织。`daily/` 管理正式行动、双环和手牌，`workspace/` 提供唯一生产写入口、本地存储与恢复点；旧 Planner 保留为只读兼容。公开接口与并行边界见[模块地图](../架构/README.md)。测试及合成样例位于 `tests/` 和 `tests/fixtures/`。

```sh
cd app
npm test
npm run test:independent
npm run build
npx playwright install chromium
npm run test:browser
```

GitHub Actions 配置了 Node、构建与真实浏览器门禁；Playwright 为固定开发依赖，本机也可使用已安装 Chrome。执行方式见[浏览器回归说明](../../app/tests/browser/README.md)。远端结果以精确提交对应的 Actions 为准。

详细上传与私下分发检查见[分发说明](分发说明.md)。提交前请检查是否意外包含备份 JSON、真实工作区导出或个人截图。

## Roadmap

- **v0.4.0**：Today 成为正式日常页面（时间盘、手牌、排期、实际确认、批注），抽卡手牌“当日”收敛为跳转 Today，接受后返回原浏览上下文；验收与整理记录见[版本索引](../归档/v0.4/README.md)。
- **v0.3.0**：工坊、库存、槽位、球面、堆叠与归档已接入；最新结果以[v0.3 版本记录](../归档/v0.3/README.md)为准。

- **版本 v0.2.0**：正式行动闭环与备份恢复已接入；下述验收针对该实现。GitHub 上传状态及复现要求见[分发说明](../使用/分发说明.md)。
- **当前验收（2026-10-02）**：G0—G3已放行。正式双环/手牌、主要页面统一与响应式已接入，经修复作者以外的检查者复测；见[G3验收记录](../归档/阶段0-3/测试记录/G3-2026-10-02-有界修复与最终验收.md)。
- **证据边界**：自动化浏览器覆盖生产操作、故障重试和旧G2回归；实体触屏、真实迁移/恢复、七日连续使用和完整视觉偏好仍待实际使用反馈，不自动迁移个人数据。
- **后续方向**：先积累使用反馈，再设计跨日记录、每日回顾及第二领域；这些扩展尚未实现。
