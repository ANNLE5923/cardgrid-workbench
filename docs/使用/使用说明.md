# CardGrid · 卡格工作台

CardGrid 是一个以 Today 为入口的本地优先个人工作台，帮助你把每天的安排、临时想法和行动放在同一处，并看清计划如何变成实际执行。

## 为什么做？

日程在日历里、待办在任务软件里、想法在笔记里；每天开始时，人仍要自己回答“今天该做什么”。CardGrid 从这个问题出发：先看今天，再调整安排并采取行动。它面向想自行管理时间和任务的个人用户，不以团队协作为当前目标。更完整的方向见[项目定位与 README 规范](../项目定位说明.md)。

## 核心特点

- **Today 优先**：先理解今天的安排和重点，再决定下一步行动。
- **从空白开始，自主配置**：自己建立日型、星期安排和卡片定义。
- **先捕获，再整理**：临时想法进入 Inbox，不会自动变成当天任务。
- **区分安排与变化**：当天调整不必改写长期日型模板。
- **本地优先**：无需账号，工作数据保存在当前浏览器，由你导出备份。

## 当前功能

### Today

查看完整时间记录，快速记录想法。旧版列表保留为只读兼容；新排期、改期和实际确认在“抽卡手牌 → 当日”完成。首次打开为空白工作台。

### Inbox

保存快速记录，捕获时不必填写日期、优先级和项目；旧记录以兼容视图展示。

### Schedule

查看完整安排，显式准备日型；模板可通过统一配置 JSON 编辑。固定块解锁与调整、计划撤回在“抽卡手牌 → 当日”完成。

### 行动定义与抽卡手牌

自建定义、抽取/重抽/手选、排序手牌、排期、确认分钟精度实际区间。“当日”视图提供正式双环时间盘和可拖动手牌：5分钟落点、改期与外拉撤回；所有操作都有按钮或表单路径。重叠须确认，固定修改须解锁；已确认事实只读，可追加批注。

### 制卡工坊与每日库存（v0.3）

先建书目，在“卡池”建立书目池并勾选成员；再建行动原卡，例如 `阅读《{书名}》`，添加标签为“书名”的槽位并绑定该池。每张卡的槽位标签必须不同。无槽普通行动也可直接使用。

在“生成规则”选择原卡，设置每日/指定星期、开始日期与时区。进入抽卡手牌会协调今日库存。球面第一下选中具体卡，第二下翻开；也可直接手选副本。槽位下拉的第一个可选项“随机”立即固定书目，只有你主动再选随机才重抽。检查组合文字后接受，再到“当日”排期或记录实际。

手牌 `×n` 是多份独立行动，展开后逐份操作并查看来源日。副本在来源日 D 至 D+6 保留，D+7 起归档并撤销未完成排期；接受、改期不延长来源期限。事实和批注保留在“归档日志”。同一天有意再次接受会新增独立行动；保存失败的“重试本次保存”只确认原命令，不重复创建。

关闭期间不后台生成；启动、回到可见状态与可见页面规则时区午夜进行协调。只自动生成当前日，漏日可从“手动补生成漏日”选择规则和来源日期补回。未来、超出保留期或没有当日版本证据的日期会拒绝。小屏/减少动态效果默认静止列表，两步翻牌规则相同。

### 配置与本地数据

在配置工坊维护卡片定义等配置；在“数据与备份”导入或导出配置包、下载完整备份，并通过导入备份恢复数据。

## 开始使用

需要 **Node.js 22.18+（22.x）或24+**。先下载源码，或克隆仓库后进入项目目录：

```sh
git clone https://github.com/ANNLE5923/cardgrid-workbench.git
cd cardgrid-workbench
```

然后运行：

```sh
npm ci
npm run dev
```

然后在本机浏览器打开 <http://127.0.0.1:4173/>。Windows 用户也可以双击 [scripts/启动卡格工作台.bat](../../scripts/启动卡格工作台.bat)。开发服务器只监听本机回环地址，局域网设备无法直接访问；关闭服务器窗口即可停止。

首次使用可在“行动定义”创建一条定义，点击“加入手牌（手选）”，再到“抽卡手牌 → 当日”安排并确认实际。重复日型在配置 JSON 中编辑，在 Schedule 显式准备；查看或切日期不会自动生成安排。

## 数据与隐私

- 无需账号。数据保存在当前浏览器的 IndexedDB，应用不会主动将工作区数据上传到服务器。
- 数据按浏览器来源和用户配置隔离；换浏览器、设备或端口，或清除站点数据，可能看到另一空白工作区或失去本机数据。
- 定期从“数据与备份”下载完整备份，并妥善保管。备份可能含有私人日程和记录，请勿随源码公开。
- IndexedDB 不是加密保险箱；能访问本机浏览器配置文件的人可能读取其中数据。
- 离线缓存只包含应用文件，不缓存工作区数据。

### 从旧版本升级

旧备份按原 Data v2 精确恢复，日常排期仍可使用。新工坊需要 Data v3：进入“数据与备份”，下载完整备份并确认文件已保存，预览升级内容，再明确执行升级。读取旧工作区不会自动升级。ConfigV3 只含配置与工坊目录，不能替代含库存、手牌、事实和日志的完整 BackupV3。

## 开发说明

[文档入口](../README.md)汇总当前设计、正式合同和[已完成开发归档](../归档/阶段0-3/README.md)。

应用使用 React、TypeScript 和 Vite；工作数据保存在浏览器 IndexedDB 中。源码按 `app/`、`workshop/`、`drawing/`、`daily/`、`workspace/`、`shared/` 组织。`daily/` 管理正式行动、双环和手牌，`workspace/` 提供唯一生产写入口、本地存储与恢复点；旧 Planner 保留为只读兼容。公开接口与并行边界见[模块地图](../架构/README.md)。测试及合成样例位于 `tests/` 和 `tests/fixtures/`。

```sh
npm test
npm run test:independent
npm run build
npx playwright install chromium
npm run test:browser
```

GitHub Actions 配置了 Node、构建与真实浏览器门禁；Playwright 为固定开发依赖，本机也可使用已安装 Chrome。执行方式见[浏览器回归说明](../../tests/browser/README.md)。远端本轮运行尚需提交后验证。

详细上传与私下分发检查见[分发说明](分发说明.md)。提交前请检查是否意外包含备份 JSON、真实工作区导出或个人截图。
